# Translating

User-facing strings live in `i18n/`. English is the source. `scripts/i18n.mjs` checks the catalog and writes the files the apps load.

## 1. Locales

`i18n/locales.json` registers four locales. Each entry has `code`, `name`, `dir`, `android`, and `required` (`scripts/i18n.mjs`, `LOCALE_FIELDS`).

| code | name | dir | Android folder | required |
| --- | --- | --- | --- | --- |
| `en` | English | `ltr` | `values` | true |
| `ar` | العربية | `rtl` | `values-ar` | true |
| `pt-BR` | Português (Brasil) | `ltr` | `values-pt-rBR` | false |
| `es-419` | Español (Latinoamérica) | `ltr` | `values-b+es+419` | false |

English is the source (`SOURCE` in `scripts/i18n.mjs`). The registry must include `en`. Each code and each Android folder appears once. At most one locale has `dir` `rtl`. Today that locale is `ar`.

`required: true` means a missing file or a missing key is an error. `required: false` means a missing file is allowed. A missing key in a file that does exist is a warning (`untranslated`), and an extra key is still an error.

A locale file can lag behind English. At run time a missing translation uses English:

- Bot: `messages[locale][key]`, then `messages.en[key]`, then the key (`src/utils/i18n.cjs`, `createTranslator`).
- Dashboard: `translations[language][key]`, then `translations.en[key]` (`frontend/src/context/I18nContext.tsx`). `frontend/src/i18n/translations.ts` holds `{}` for a locale that has no `dashboard.json`.
- Gateway: `DICT[lang][key]`, then `DICT.en[key]` (`public/gateway-i18n.js`).
- Command docs: the locale string, then English (`src/utils/commandDocs.cjs`, `attachCommandDocs`).

## 2. Catalog layout

Each locale directory holds the same files. A file is a flat object. A value is a string. In `android.json`, `commands.json`, and `bot/<area>.json` a value may be a plural object whose keys are CLDR categories and which includes `other`. Dashboard and gateway values stay strings (`scripts/i18n.mjs`, `checkValue`).

| File | Surface |
| --- | --- |
| `dashboard.json` | React dashboard, `frontend/src/i18n/translations.ts` |
| `gateway.json` | Login, setup, and QR pages, the `DICT` block in `public/gateway-i18n.js` |
| `android.json` | `android/app/src/main/res/<folder>/strings.xml` |
| `commands.json` | `description` and `usage` on commands |
| `bot/<area>.json` | Bot replies |

Bot areas today: `ai`, `core`, `group`, `help`, `lang`, `moderation`, `schedules`, `stickers`, `tools`. A new `bot/<area>.json` is picked up because the loader reads every JSON file in `bot/` (`loadCatalog`).

Dashboard, gateway, and Android keep the key names those surfaces already use. Node joins the file and the key (`nodeMessages` in `scripts/i18n.mjs`):

- Key `ping.pong` in `bot/core.json` is `bot.core.ping.pong`.
- Key `ping.description` in `commands.json` is `commands.ping.description`.
- A group sub-command uses `group.<name>.description` and `group.<name>.usage` in `commands.json`. `attachCommandDocs` reads `commands.group.<name>.<field>` when the command's category is `group` (`src/utils/commandDocs.cjs`).

`i18n/` is not in the npm `files` list (`package.json`). Node loads `src/i18n/catalog.generated.cjs`.

## 3. Editing

1. Edit the JSON under `i18n/`. Add the key to English and to every locale with `required: true`. Today that is `en` and `ar`.
2. Run `npm run i18n:build` (`node scripts/i18n.mjs build`). Build rewrites the generated files after the catalog loads. It does not run the validator. A load error (bad JSON, a missing `locales.json`, `notes.json`, or `review.json`, an unknown file, a locale folder that is not in the registry) stops the write.
3. Commit the JSON and the generated files together.
4. `npm run i18n:check` fails when validation fails or a generated file differs. `npm test` runs `tests/i18n-catalog.test.mjs`, which requires zero validation errors, zero untranslated warnings, and generated files that match.

`i18n:check` prints untranslated keys and review hash mismatches. Those two lines do not by themselves fail `i18n:check`. The catalog test fails the suite on an untranslated warning.

Leave these files to the generator. Each starts with `Generated by scripts/i18n.mjs from i18n/. Do not edit.` (`GENERATED_BY`):

- `src/i18n/catalog.generated.cjs`
- `frontend/src/i18n/translations.ts`
- `public/gateway-i18n.js`, only the block between `// <i18n:generated>` and `// </i18n:generated>`. The rest of that file is hand-written.
- `android/app/src/main/res/<android folder>/strings.xml` for each locale that has `android.json`. Today that is `values/strings.xml` and `values-ar/strings.xml`.
- `android/app/src/main/res/xml/locales_config.xml`

`values-pt-rBR/strings.xml` and `values-b+es+419/strings.xml` appear when those locales have `android.json`.

## 4. Validator

`npm run i18n:check` runs `validate` in `scripts/i18n.mjs`. These are errors:

- The registry fields, duplicate codes, duplicate Android folders, and a second `rtl` locale, as in section 1.
- Duplicate JSON keys. The checker scans the raw text (`jsonDuplicateKeys`). `JSON.parse` would keep the last copy.
- Key parity with English. A required locale must have the same keys. Any locale that adds a key English does not have fails, including a locale that is not required.
- Empty strings, and empty plural categories.
- Plural objects only in `android`, `commands`, and `bot`. Each plural includes `other`. A category must be one `Intl.PluralRules` reports for that locale (`categoriesFor`). For `pt-BR` and `es-419` those categories are `one`, `many`, and `other`. For `en` they are `one` and `other`. For `ar` they are `zero`, `one`, `two`, `few`, `many`, and `other`.
- Placeholders. Outside Android, `{name}` names (`{` plus `[A-Za-z_][A-Za-z0-9_]*`) are compared as a set with English. The count of one name is not compared. Android compares positional tokens `%1$s`, `%2$d`, and the same shape (`%\d+$` plus a letter) as a bag: the count of a token is the most times it appears in any one plural category.
- In a bot or commands plural, every category's `{name}` set must match the English plural's set, and every category's `*` count and backtick count must match the English `other` string.
- In a bot or commands string, the `*` count and the backtick count must match English.
- HTML. A value that contains `<` plus a letter, `/`, or `!` fails, except two cases. Gateway keys used as `data-i18n-html` in `views/*.ejs` may use only the tag names present in the English value (`findHtmlKeys`, `markupIssues`). Those keys today are `loginTrust`, `setupTrust`, `qrTrust`, `qrStep1`, `qrStep2`, `qrStep3`, and `qrCallout`. A translation may omit one of those tags. It may not add a tag. `commands.json` and `bot/` strings skip this check because usage contains text such as `<member>`. Plural categories in those files are still checked.
- `i18n/notes.json` is an object. Each note is a string. The key must exist in the matching English file (`validateNotes`). Android notes are written as XML comments on the English `strings.xml` only (`renderAndroidXml`).
- `i18n/review.json` is an object. See section 8. A bad shape is an error. A stale hash is not.

## 5. Android

Write positional tokens in `android.json` as `%1$s` or `%1$d`. Put the plain text in the JSON. `escapeAndroidString` in `scripts/i18n.mjs` writes the XML.

It escapes `\`, `'`, `"`, newline, tab, carriage return, `&`, `<`, and `>`. It then keeps a positional token as written and turns any other `%` into `%%` (`escapeAndroidPercents`). A value whose text starts with `@` or `?` gains a leading `\`. A value that starts or ends with a space is wrapped in quotes.

`language_name_ar`, `language_name_en`, `language_name_pt_br`, and `language_name_es_419` are the native names in `i18n/en/android.json` and `i18n/ar/android.json`. `MainActivity.kt` shows those strings in the picker. Copy the same four values into every locale. The validator does not special-case them.

`locales_config.xml` lists every registry code, in `locales.json` order (`renderLocalesConfig`). `AndroidManifest.xml` points at it with `android:localeConfig="@xml/locales_config"`.

## 6. Bot replies

New replies call `t(key, params)` from `src/utils/i18n.cjs`. `t` reads the current language, then English, then returns the key and logs `Missing bot translation` once. Parameters replace `{name}` as plain strings. A missing parameter leaves the token. A plural value uses `Intl.PluralRules` on `params.count`, then `other`.

`tr(en, ar)` returns the Arabic string when the current language is `ar`, and the English string for `en`, `pt-BR`, and `es-419`. No user-facing call uses it. The two remaining calls send text to the AI model (`src/services/aiAgent.cjs`, `src/services/aiProviders.cjs`); each has `// i18n-exception: sent to the model` on the line above. A new call that must stay on `tr()` needs the same marker with its reason.

Arabic number words (dual and plural forms) are plural objects: the Arabic categories `zero`, `one`, `two`, `few`, `many`, `other` reproduce them (`bot/stickers.json` `count.*`, `bot/schedules.json` `recurrence.hourly`). Dates use `intlTag()` from `src/utils/i18n.cjs`: `en-GB`, `ar-EG`, `pt-BR`, `es-419`.

`withLang(lang, fn)` runs `fn` in `ar`, `en`, `pt-BR`, or `es-419`. Any other value runs as `ar` (`src/utils/i18n.cjs`). That is separate from the English fallback for a missing catalog key.

## 7. Language settings

Three settings. They are independent.

Dashboard UI language is client state. `public/ui-boot.js` reads the Android host, then `localStorage` key `levix_lang`, then the browser language. The header and Settings save through `setLanguage` in `frontend/src/context/I18nContext.tsx`. It is not a `bot_settings` row. The shared subtag rule is in `frontend/src/i18n/locale.ts`, and the boot script repeats it: `ar` to `ar`, `pt` to `pt-BR`, `es` to `es-419`, `en` to `en`. Anything else is English. `dir` is `rtl` only for `ar`.

`bot_language` is a database setting (`src/config/settings.cjs`). The choices are `auto`, `ar`, `en`, `pt-BR`, and `es-419`. The default is `auto`. `!lang` accepts `auto` and the same four codes, plus `pt` and `es` (`src/commands/lang.cjs`, `normalizeLocale`). `auto` uses `detectLang` (`src/utils/i18n.cjs`): Arabic letters select `ar`, English words select `en`, and everything else selects `ar`. `auto` never selects `pt-BR` or `es-419`. Those two come from an explicit choice.

`ai_reply_language` is a database setting. The default is `follow_bot`. The choices are `follow_bot`, `auto`, `ar`, `en`, `pt-BR`, and `es-419` (`src/config/settings.cjs`). `botLangDirective` in `src/services/aiAgent.cjs` uses `ai_reply_language` when it is `auto`, `ar`, `en`, `pt-BR`, or `es-419`. Any other value, including `follow_bot`, uses `bot_language`. `auto` tells the model to answer in the language the user writes. The four fixed values tell it to answer in that language.

## 8. Review

The `pt-BR` and `es-419` files start as machine drafts. Each is recorded in `i18n/review.json` with `status` `draft` until a review is recorded.

`review.json` maps `<locale>/<file>` to an object with `status`, `by`, `date`, and `sha256` (`REVIEW_FIELDS`). `<file>` is `dashboard`, `gateway`, `android`, `commands`, or `bot/<area>`, without `.json`. `status` is `draft` or `reviewed`. The other three fields are non-empty strings. `sha256` is the hex digest of that file's bytes. The checker compares it in lower case (`reviewMismatches`).

The owner decided that ChatGPT is the approved reviewer for `pt-BR` and `es-419` and that native-speaker review is not required to merge (Q-19, amended 2026-11-02). A `reviewed` entry names that review in `by`, for example `ChatGPT targeted machine review (Q-19); machine translation, not native-speaker certified`. Never record a review that did not happen, and never describe a file as native-speaker reviewed. When keys are added to a reviewed file, set it back to `draft` and say in `by` what was not reviewed. The script does not check the reviewer name.

`npm run i18n:check` prints `review <locale>/<file>: sha256 does not match the file` when the bytes differ or the file is missing. The print does not fail the check. Update `sha256` when a reviewed file changes.

A Phase 10 release gate that lists files still marked `draft` is planned. `scripts/i18n.mjs` does not do that.

The validator enforces the backtick count in bot files and `commands.json` (section 4). It does not check that the words inside the backticks stayed the same. Keep them the same anyway.
